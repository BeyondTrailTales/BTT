## Component Design Specifications

### Card Component States
```
Default State:         Hover State:          Active/Selected:
┌─────────────┐       ┌─────────────┐       ┌═════════════┐
│             │       │ ↗️          │       ║ ✓           ║
│   Content   │       │   Content   │       ║   Content   ║
│             │  →    │             │  →    ║             ║
│ [Action]    │       │ [Action]    │       ║ [Action]    ║
└─────────────┘       └─────────────┘       ╚═════════════╝
                      + shadow & glow        + border glow
```

### Button Hierarchy
```
Primary:              Secondary:            Tertiary:
┌─────────────┐      ┌ ─ ─ ─ ─ ─ ─ ┐      ─ ─ ─ ─ ─ ─ ─
│ Take Action │      │   Support    │        Text Only
└─────────────┘      └ ─ ─ ─ ─ ─ ─ ┘      ─ ─ ─ ─ ─ ─ ─
Neon glow            Glass effect          No background
```

### Progress Indicators
```
Linear Progress:      Circular Progress:    Step Progress:
━━━━━━━━━━━━━━━━     ┌─────────────┐       ●━━━●━━━○━━━○

                     │    ╱─────╲   │
                     │   │       │  │
                     └─────────────┘
```

- Keyboard shortcuts

## Implementation Notes

1. **Consistency**: Use the same card styles, button patterns, and color coding across all pages
2. **Feedback**: Every action should have immediate visual feedback
3. **Progress**: Show users where they are in multi-step processes
4. **Connection**: Make relationships between features visually obvious
5. **Guidance**: Use empty states and tooltips to guide users
6. **Performance**: Optimize animations for 60fps on all devices
7. **Accessibility**: Ensure all interactions work with keyboard and screen readers
